# 2026-11-03 短回复与调用前冷却

后续更新：10字符不再是固定限制。参数页支持max_reply_chars（1~2000）、short_reply_weight / medium_reply_weight / long_reply_weight（0~1000，至少一个非零）；预算随上限自动分为1/3、2/3、全长。旧配置兼容，默认值保持10和65/25/10。以下10字描述为初始默认方案；当前生成、手工编辑和发送兜底均使用用户设置的上限。

- 每条QQ消息硬上限10字符，包含标点；不通过拆长句连发绕过限制。
- 每轮以65/25/10权重抽样3/6/10字符预算，提示词鼓励自然短句。模型超预算时本地截短，发送兜底再次检查；人工编辑超长则拒绝并保留候选供修改。
- 沿用Tuning.cooldown值，默认30秒。最后一条成功发送后开始计时，单条发送也启动冷却。
- 新消息先显示、写入加密记忆，再在入队前检查发送中/冷却状态；worker调用前再检查，避免既有队列绕过。
- 发送期间也阻止新候选调用；冷却开始清空触发队列，不在期满后补答旧消息。
- JSON重试前再次检查调用许可；若期间开始发送或进入冷却，停止重试。已发生的调用计费不能追溯撤回，返回结果在冷却时不生成候选。
- 冷却期间暂停启动记忆反思，避免额外模型消耗。接收、显示、/stop和停止按钮继续有效。
- 59项测试通过，新增覆盖冷却零调用、旧队列不重放、连发阻止调用及末条计时、三档长度硬上限、手工超长保留候选及格式重试门禁。

构建仍使用唯一正式程序dist/QQPersonaAgent.exe，旧exe只备份到项目外维护目录。
